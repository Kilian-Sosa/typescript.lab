# M3 public static runner — security design review (proposal only)

Date: 2026-10-18. **Design-only. Not an authorization to create protection exceptions, publish public assets, merge PR #9, deploy Production, alter DNS, or enable Production execution.**

## Decision and specification impact

**Recommended next experiment:** one time-boxed, exact-domain **Preview Deployment Protection Exception** for the *existing runner* QA alias only, following an explicit new owner approval. Keep the existing app project protected and both Production bootstraps inert. Verify normal authenticated app → **public runner iframe** without any automation-bypass tokens, query parameters, browser CSP exemptions, or third-party-cookie allowances. Restore the exception/QA aliases afterward.

The specification already describes a separate **static unauthenticated runner site**. The user-visible product specification does not change. This proposal fills a hosting-security gap; if approved for implementation, update the deployment/acceptance plan and produce independent review before changing settings.

## Threat model for making static runner publicly reachable

Trust boundary: app may hold private drafts/session data; runner host and all learner input must be considered untrusted. A third-party attacker can visit/download runner static files, embed/copy assets, exhaust CDN bandwidth, or attempt to control messages or hostile learner TypeScript. They must **not** gain app DOM, cookies, storage, authenticated network access, credentials or trusted grading. Browser runtime exhaustion and static-bandwidth abuse are distinct risks.

| Boundary | Required invariant | Current evidence and residual risk |
| --- | --- | --- |
| Separate browser **site**, not merely origin | A and R have independent registrable sites; cookies and storage do not cross. `vercel.app` is on the public-suffix list. | Hosted Edge synthetic canary checked cookies and localStorage; expand IndexedDB and additional browsers. Do not replace R with same registrable-domain sibling subdomain without new cookie/site threat review. |
| Public static-only runner | Only vetted HTML, hashed JS Worker and WASM; no functions, APIs, auth configuration, env, analytics, source maps, telemetry or user data persisted at R. No code execution at Vercel server. | Reviewed Vercel Build Output v3 was delivered and hashed; verify public via ordinary unauthenticated HEAD/GET; check `404` and all MIME types. Public content reveals harness and canonical cases; no secret test fixture or server-grade scoring claim. |
| Browser embedding | App CSP `frame-src R` exactly; runner page `frame-ancestors A` exactly; app iframe has `sandbox="allow-scripts allow-same-origin"` **only because R is a separate site**. | Existing audited code enforces this. Negative probes for third-party framing, top-level activation, hostile redirects, DOM/storage, navigation and popups. Do not loosen to `vercel.com`, wildcards or `unsafe-eval`. |
| Message trust | Runner only accepts messages from the configured exact `A` window/origin and fresh nonce; app only accepts from exact `R` iframe/window, schema/cases/nonce/revision. | Controlled hosted forged empty pass and stale revision tested; further wrong-origin/source/replayed/oversized cases needed on public path. Browser-reported test results remain educational, never authoritative. |
| QuickJS VM | Compiled learner code evaluates only in QuickJS, not native page/Worker JS or Vercel Functions. Worker CSP permits same-origin WASM only, no arbitrary network/modules/nested workers. | Controlled hosted real VM/WASM and timeout/cancel passed; need public-path host API probes, source/memory/stack/output budgets and VM exhaustion in more browsers. |
| Cost/abuse | A public URL exposes static transfer and asset download to any visitor; browser CPU runs on visitors' devices, not in Vercel Functions. | Capture baseline bytes and costs, monitor 4MB-class static payloads and bandwidth; validate plan fair-use; avoid introducing a public server evaluator. No authentication token hidden in public JS is meaningful protection. |
| Hosting configuration | Only the **exact runner Preview alias R** is excepted; app QA, generated immutable URLs and both Production domains remain SSO-protected. | Vercel exceptions are domain-scoped and persist across alias reassignment: **freeze R mapping**, watch for drift and remove exception before any alias movement or code update. Never add an exception for app. |

## Recommended owner-authorized public Preview experiment

**Stage 0 — read-only gate (must repeat immediately before any write)**

1. Verify exact team and two project IDs; PR #9 head/source/review/CI; SHA-1/256 artifact manifests and actual deployed HTML+Worker CSP. Confirm Vercel runner project's `Add Domain` is available **without upgrade or billing**.
2. Confirm no project Git connection, no existing exceptions or automation-bypass secrets; both QA aliases on inert discovery and both Production bootstraps still sole inert deployments.
3. Validate that the runner artifact has no functions/API/auth/integrations. Snapshot Vercel project usage before exposure; record the operator, clock-start time and budget baseline. Run `node scripts/m3-public-qa-probe.mjs protected` and confirm every required domain remains protected.

**Operator and maximum duration:** one designated, continuously present **infrastructure operator** (the owner-authorized CoS/Vercel coordinator) holds sole responsibility for exception creation, monitoring, emergency rollback and final verification. The owner must explicitly identify an available backup operator or accept the single-operator interruption risk before exposure. Begin the timer when the exception is confirmed active. **30 minutes absolute maximum**, not reset by errors or retries: allocate at most **20 minutes for tests** and **10 minutes for revocation, verification and rollback**. Stop tests immediately on any threshold or security failure. No unattended exposure and no assumption that the platform automatically expires exceptions.

**Measurable experiment budget (operator's controlled traffic, not a platform-enforced quota):**

- Baseline built runner: ~7.85 MB across 11 static files, including a ~3.53 MB hashed Worker bundle and WASM variants. Verify actual transfer sizes at test time rather than treating these uncompressed artifact sizes as network measurements.
- Stop at **256 MiB total recorded response-body transfer** or **400 requests** from controlled test clients, whichever happens first; at most **two concurrently active browser contexts**, at most **one active runner Worker per iframe**, and at most **60 end-to-end Run tests actions** across all browsers. Abort if counters cannot be measured; do not blindly continue on telemetry failure.
- Separately monitor Vercel project usage/network analytics at test start and at least every **5 minutes**; stop immediately on a suspicious unexpected increase (more than **256 MiB** of additional outbound data or **400 requests** not attributable to test controllers), or when a metered/paid resource is requested. Analytics may lag: these thresholds are **stop signals, not guarantees against external traffic or bills**. No claim of a server-enforced usage cap.
- **Owner-scoped QA matrix (2026-10-19):** require current Microsoft Edge on Windows desktop at 1280×900 and Edge/Chromium at a **390×844 simulated mobile viewport**, plus an ordinary authenticated desktop Edge browser with third-party cookies blocked during iframe interaction. Record actual versions, TLS result, timings and request bytes. **Firefox and WebKit are explicitly waived by the owner for this bounded QA experiment: do not install them, run them, call them unsupported, or claim cross-browser coverage.** Physical iOS/Android and native Safari are likewise **not tested**; viewport emulation is not a physical-device result. Wider compatibility remains a separate release-risk decision.
- **Required pass conditions for each tested Edge configuration:** unauthenticated runner public 200 HTML/Worker/WASM with correct MIME/CSP, immutable runner URL still 302 to SSO, app QA and Production URLs still protected, genuine iframe and 14/14 cases, false-result rejection, wrong answer and compiler/runtime errors, banned imports/network, independent 3-second hard watchdog, cancellation/disposal, stale-run rejection, cross-site DOM/storage/IndexedDB/cookie isolation, responsive layout/keyboard/live status. Record 200% zoom, offline/reconnect and cold/warm-cache behavior. A failure or untested **mandatory in-scope** case is NO-GO, not partial approval. Passing Edge alone establishes only an **Edge-scoped QA GO**, not broad production browser compatibility.

**Stage 1 — limited public-preview exposure (requires separate explicit owner approval)**

1. Temporarily move runner alias R to the exact reviewed READY **Preview** runner deployment; app alias A to exact reviewed READY Preview app deployment; read back project/deployment/target/SHA and SSO.
2. Add exactly **one** protection exception: `typescript-lab-m3-runner-qa.vercel.app`, **only on the runner project**. Do not disable project-wide SSO. Do not alter default Production runner aliases, app SSO or Git.
3. Verify from an **unauthed, clean network/browser**: R alias serves HTML, hashed Worker and WASM directly with HTTP 200, exact CSP/no-store/nosniff, valid HTTPS and no SSO redirect; runner's generated immutable deployment URL **still redirects to SSO**. A alias and both Production hostnames must still require SSO. If any scope widens, immediately remove exception and restore aliases.
4. Verify **ordinary authenticated app browser → public iframe runner** with no test header, cookies, URL credential, third-party-cookie change or browser unsafe flags. Include explicit third-party-cookie-blocked profile and fresh browser contexts. Only after success proceed to hosted functional/adversarial suite.
5. Re-run hosted Q5/Q6 full negative suite, including parent/runner DOM+storage+cookies+IndexedDB, Worker network/imports, injected messages, Worker watchdog/heap, memory/stack/output/source caps, 404/MIME/response headers, concurrency and browser compatibility. The existing VM limits remain **32 KiB source, 1 MiB input, 64 KiB output, 32 MiB QuickJS runtime memory, 128 KiB stack, 2-second VM interruption and independent 3-second Worker watchdog**; these are not overall browser memory guarantees. Collect actual pass/fail, browser versions, request/transfer totals and observed runtimes. Use the read-only `scripts/m3-public-qa-probe.mjs public` first; the authenticated ordinary-browser editor test must use a logged-in user browser, **not** an automation-bypass header, injected cookie, or modified CSP.

**Reproduction sequence, without credentials in scripts:**

- Before exposure: `node --test scripts/m3-public-qa-probe.test.mjs`, `node scripts/m3-public-qa-probe.mjs protected`, `node scripts/m3-public-qa-browser.mjs plan`; dry-run `powershell -File scripts/m3-public-qa-inert-fallback.ps1`. Confirm operator/backup, timeout, project usage baseline, runner/browser versions and Vercel alias IDs. No Firefox or WebKit installation or testing.
- Immediately after exception: `node scripts/m3-public-qa-probe.mjs public`, then `node scripts/m3-public-qa-browser.mjs public` (unauthenticated static runner in Edge desktop and simulated mobile viewport only). These commands make read-only requests only; a nonzero result halts acceptance.
- Using an already Vercel-authorized normal browser at `A/challenges/longest-window`, fill the canonical local `challenges/longest-window/solution.ts`, run exactly 14 canonical cases, then wrong answer, semantic error, forbidden import, runtime error, timeout and cancellation. Verify zero iframe remnants and accessible feedback; no bypass secret, test-only cookies, source in URL, weakened CSP or invalid TLS flags. Reproduce spoofed/replayed/stale/budget cases against the same HTTPS pair with the existing reviewed security fixtures. Capture successes **and** failures with the full version/context; do not call the static probe evidence of iframe functionality.
- Record per-batch browser version, requests, actual response-body bytes, active context count, `Run tests` count, elapsed minutes, immutable deployment IDs and app/runner QA mappings. Stop on any mandatory failure, missing evidence, protection drift, request/byte threshold, inability to inspect network or 20-minute test cutoff. Run revocation and verification before the absolute 30-minute maximum.
- After protection removal and inert-alias restoration: `node scripts/m3-public-qa-probe.mjs reprotected` followed by `node scripts/m3-public-qa-probe.mjs protected`, plus independent Vercel API/dashboard mapping/exception readback. These HTTP probes cannot prove exception removal by themselves—dashboard state is a separate required gate.

**Stage 2 — unconditional rollback after test**

1. **Remove the exception first** while R still points at the reviewed deployment. Verify the exception is absent in the Vercel dashboard and that `node scripts/m3-public-qa-probe.mjs reprotected` sees unauthenticated R return 302 to Vercel SSO. **Do not move either alias before this normal path succeeds.**
2. Reset A/R to their exact inert Preview discovery IDs. Verify via Vercel API that the two aliases map to the recorded IDs; check immutable Preview and default Production aliases, project SSO `all`, empty exception/bypass lists, no Git links. Re-run `node scripts/m3-public-qa-probe.mjs protected` from an unauthenticated client. Do not call rollback complete on the basis of a successful CLI/UI click.
3. Record sanitized evidence (without learner source, tokens, user state), full deployment hashes and exact gaps, and obtain focused independent hosted security reassessment. PR #9 stays draft; no Production approval is implied.

**Emergency if exception removal fails, stalls, or its status is uncertain:** stop the suite immediately; **restore R to the reviewed inert runner Preview** `dpl_4bj2D2yd12FQQFo1U3q7MbPXU9Po` even while the exception persists, using the reviewed CLI/connector alias action (prepared guarded operator aid: `scripts/m3-public-qa-inert-fallback.ps1`). Verify R→inert ID through the authenticated Vercel API and unauthenticated public HTML inspection showing the inert notice with **no Worker/WASM**. Keep trying to remove the exception and escalate to the owner/Vercel support. The inert notice may remain publicly reachable while the exception is active; **do not claim the domain is protected**, even if no runnable payload remains. Restore the app QA alias to its inert ID separately; recheck the runner alias stays inert after each retry. Report rollback **incomplete** until (1) exception absent on Vercel, (2) unauthenticated R returns SSO 302, (3) both aliases resolve to the exact inert Preview IDs, and (4) both Production bootstraps and project SSO are unchanged. If the absolute 30-minute window is exceeded, escalate an open security incident rather than declaring success.

On any other error, remove exception immediately, verify R returns SSO and restore aliases. Stop rather than enabling a wildcard/broad bypass; if an upgrade is requested, stop without paying. Never ship test credentials to JavaScript. The operator must remain available for the full cleanup, including failures.

## Production delivery is a later, different decision

The final product will need its own **public runner Production hostname R-prod**, paired with the **actual application Production hostname A-prod**. The current `hostedQaRunnerOrigin` explicitly requires `mode=m3-hosted-qa`, Preview metadata and A/R QA aliases. It must **not** be re-used or overridden via public `VITE_*` flags to activate Production.

Plan a new exact-origin pair, separate security-approved production build/manifest, code review and CI. Vercel's Standard Protection normally protects preview/generated deployment URLs while allowing the project production domain to be public; if choosing that setup, review **project-wide** policy effects and explicitly authorize changing it. Do not repurpose or replace the existing inert bootstrap until a separate Production approval. No app OAuth/Supabase or session changes are part of the runner exception experiment. App Production publication and authentication integration require their own release gates.

## Current decision

**Design GO** for proposing a single exact-domain public QA Preview experiment, conditioned on separate authorization, source/header/protection checks, strict rollback and fresh independent review. **No GO** for making any domain public today, normal-user delivery, Production runner upload, or merging PR #9. The already-completed controller-bypass hosted tests demonstrate technical viability only; they are not evidence of normal-user delivery.

**Independent design-review status:** the owner's conditional security review identified and required closure of P2 rollback/measurement issues and P3 documentation currency; the remedies are specified here. The prior attempted CoS independent-review worker could not start; ensure an independent reviewer approves the final **amended plan and probe tooling** before exposing the QA domain.
